# Карта ИТ-предприятия · Globus IT

Интерактивная одностраничная карта классов корпоративных ИТ-решений. Пользователь рассматривает «разрез» условного предприятия — **два этажа** с переключателем: этаж 1 «Операции» (цех, склад, данные, продажи, бэк-офис) и этаж 2 «Технологии и люди» (кибербез/SOC, Big Data и ML, связь, ИИ и автоматизация, HR). Клик по любой системе открывает карточку класса: что это, какую боль решает, эффект в цифрах, вендоры Globus и смежные классы.

На карте показаны **45 ключевых классов** (по 5 комнат на этаже), в **словаре — все 75** решений из каталога.

Сайт закрыт **паролем для входа**, а контент (карточки, зоны, тексты шапки) и пароли редактируются в **админке**. Фронтенд — статический HTML/React, бэкенд — serverless-функции Vercel с хранилищем (Vercel KV / Upstash Redis). Деплой автоматический по `git push`.

- **Прод:** https://it-enterprise-map.vercel.app
- **Админка:** https://it-enterprise-map.vercel.app/admin.html
- **Репозиторий:** https://github.com/Tonysaaa2024/it-enterprise-map

---

## Доступ

- **Сайт** (карта) открывается только после ввода пароля на `/login.html`.
- **Админка** (`/admin.html`) — отдельный вход по паролю администратора. Админ автоматически видит и карту.
- Оба пароля меняются в админке (вкладка «Доступ»). Хранятся в виде scrypt-хэша.
- Пароли по умолчанию при первом запуске задаются переменными `DEFAULT_VIEWER_PASSWORD` / `DEFAULT_ADMIN_PASSWORD` (если не заданы — `globus` / `globus-admin`). **Смените их в админке сразу после первого входа.**

Сессия хранится в подписанной httpOnly-cookie (HMAC, секрет `AUTH_SECRET`), срок — 30 дней.

```
IT CLASSES WEB SITE/

├── login.html        # страница входа на сайт (пароль зрителя)
├── admin.html        # админка: редактор контента + смена паролей (React)
├── package.json      # зависимость @upstash/redis
├── api/              # serverless-функции (Node)
│   ├── content.js    #   GET контент (зритель) · POST сохранить (админ)
│   ├── login.js      #   вход (viewer|admin) → cookie
│   ├── logout.js     #   выход
│   ├── session.js    #   статус сессии { viewer, admin }
│   └── password.js   #   смена паролей (админ)
├── lib/
│   ├── auth.js       #   scrypt-хэши, подпись/проверка токена, cookie
│   ├── store.js      #   доступ к KV + первичное заполнение
│   └── seed.js       #   данные по умолчанию (зоны/классы/шапка) + авто-миграция формата
└── assets/
    ├── floor1.png      # диорама этажа 1 «Операции» (~4,5 МБ)
    ├── floor2.png      # диорама этажа 2 «Технологии и люди» (~4,5 МБ)
    ├── about.jpg       # слайд «О компании» (артефакт по тексту «Классы IT решений»)
    ├── pyramid.jpg     # пирамида ИТ-архитектуры (артефакт по значку ▲)
    └── globus-logo.svg
```

Внутри `index.html` фронтенд разбит на `<script>`-блоки: BuildingMap (SVG-разрез, режим «Схема»), DioramaMap (растровая диорама с хотспотами, переключателем этажей, подписями комнат, zoom/pan и режимом ручной расстановки меток), Sidebar (карточка класса), Glossary (словарь), App (оболочка), Tweaks panel (настройки). Контент (`window.ZONES`/`FLOOR_ORDER`/`CLASSES`/`HEADER`) больше не зашит в файл — он загружается с `/api/content` при старте.

## Технологический стек

- **Фронтенд:** React 18 + ReactDOM + Babel Standalone (JSX компилируется в браузере) через CDN; чистый CSS с темами; SVG для режима «Схема». Шрифты Google Fonts: Onest, Golos Text, JetBrains Mono.
- **Бэкенд:** Vercel Serverless Functions (Node, CommonJS) в `/api`.
- **Хранилище:** Vercel KV (Upstash Redis) — один ключ `content` (JSON) и `auth` (хэши паролей).
- **Аутентификация:** scrypt (хэш пароля) + HMAC-подписанный токен в httpOnly-cookie. Без внешних auth-зависимостей — только встроенный `crypto`.

Сборки фронтенда нет — Babel транспилирует JSX при каждой загрузке (для прода это можно прекомпилировать).

## Переменные окружения (Vercel)

| Переменная | Назначение |
|-----------|-----------|
| `KV_REST_API_URL` / `KV_REST_API_TOKEN` | подключение к Vercel KV (добавляются автоматически при создании KV-хранилища; поддерживаются и `UPSTASH_REDIS_REST_URL/TOKEN`) |
| `AUTH_SECRET` | секрет для подписи cookie-сессий (любая длинная случайная строка) |
| `DEFAULT_VIEWER_PASSWORD` | пароль сайта по умолчанию при первом запуске (опционально) |
| `DEFAULT_ADMIN_PASSWORD` | пароль админки по умолчанию при первом запуске (опционально) |

## Возможности

### Два режима карты
- **Диорама** — реалистичные изометрические иллюстрации двух этажей (`floor1.png` / `floor2.png`) с кликабельными хотспотами поверх. Поддерживает:
  - **переключатель этажей** (1 / 2) в шапке; при выборе класса этаж переключается автоматически;
  - **подписи комнат** над зданием (Производство, Склад, Данные, …);
  - хотспоты раскладываются ровной сеткой внутри комнаты (rect зоны) либо по сохранённым вручную позициям;
  - зум колесом мыши (к курсору), кнопками `＋ / －`, сброс кнопкой `⤢`; перемещение (pan) правой/средней кнопкой;
  - автозум к зоне при выборе класса (отключается в настройках);
  - **режим ручной расстановки меток** для админа (см. ниже).
- **Схема** — SVG-разрез здания: все зоны строками, в каждой «комнате» — классы решений (только те, что на карте). Подсветка и hover-эффекты.

### Артефакты в шапке
- Клик по тексту **«Классы IT решений»** → модальное окно **«О компании»** (слайд `assets/about.jpg`).
- Значок **▲ (пирамида)** рядом → модальное окно **пирамиды ИТ-архитектуры** (`assets/pyramid.jpg`) с зумом (колесо) и перемещением (перетаскивание), кнопки +/−/сброс. Оба закрываются по ✕/Esc/клику по фону. Слайды рендерятся из `ГЛОБУС 1 PAGER`.

### Ручная расстановка меток (только админ)
Если вы вошли как администратор, в шапке появляется кнопка **✎ Метки**. В этом режиме хотспоты можно перетаскивать мышью; кнопка **Сохранить** пишет позиции (`pos`) в хранилище — они видны всем. Классы без сохранённой позиции раскладываются автосеткой. Позиции привязаны к картинке этажа.

### Карточка класса (Sidebar)
При клике на систему слева выезжает панель:
- аббревиатура и полная расшифровка;
- синонимы и близкие названия («Также называют»);
- «Что это простыми словами»;
- «Какую боль решает»;
- «Эффект в цифрах» — 3 метрики;
- «Наши вендоры и продукты» (продукты Globus выделены цветом);
- «Типовой клиент и отрасль»;
- «Что стоит рядом» — переходы к смежным классам.

### Словарь (Glossary)
Правая панель с поиском по всем аббревиатурам, расшифровкам, названиям и синонимам. Клик по элементу открывает соответствующую карточку.

### Темизация и настройки
- Светлая / тёмная тема (кнопка в шапке).
- Плавающая панель настроек (Tweaks): режим карты, тёмный фон, автозум к зоне, пульсация маркеров.

### Управление с клавиатуры
- `Esc` — закрыть карточку и словарь.

## Модель данных

Контент хранится в KV и правится через админку; структура данных (образец по умолчанию) описана в `lib/seed.js`. На старте фронтенд получает его с `/api/content` и раскладывает в `window.ZONES` / `window.FLOOR_ORDER` / `window.CLASSES` / `window.HEADER`.

### Зоны — `window.ZONES`
Комнаты-зоны предприятия. На карте — 10 зон (по 5 на каждом этаже) + служебная зона `infra` (только для словаря, `building: 0`). Каждая зона:

```js
production: {
  id: "production",
  title: "Производство и цех",   // полное название (заголовок карточки)
  short: "Производство",          // короткая метка (подпись комнаты, ярлыки)
  accent: "#C8743A",              // акцентный цвет зоны
  tint: "#F8EDE2",                // светлый фон-подложка
  building: 1,                    // этаж: 1 (floor1.png) | 2 (floor2.png) | 0 (только словарь)
  cx: 16, cy: 60,                 // центр зоны на картинке, в % (для автозума)
  rect: { x: 7, y: 36, w: 15, h: 38 }  // прямоугольник комнаты на картинке, в % (сетка хотспотов)
}
```

Этаж 1: `production`, `logistics`, `data`, `sales`, `back`.
Этаж 2: `sec` (кибербез), `cloud` (Big Data и ML), `contact` (связь), `dev` (ИИ и автоматизация), `hr`.
Только словарь: `infra` (облако/инфраструктура).

### Порядок зон — `window.FLOOR_ORDER`
Массив id зон (10) — порядок строк в режиме «Схема». Зона `infra` в него не входит (на карте/схеме не показывается).

### Классы решений — `window.CLASSES`
Массив из 75 классов (словарь). На карте показываются те, у кого `map !== false` (45 шт.). Каждый класс:

```js
{
  code: "MES",                    // уникальный код (ключ)
  label: "MES",                   // отображаемая метка (короткая)
  zone: "production",             // id зоны (связь с ZONES)
  map: true,                      // true → на карте; false → только в словаре
  pos: { x: 24, y: 36 },          // (опц.) ручная позиция метки на картинке этажа, в %;
                                  //        нет поля → авто-сетка внутри rect зоны
  name: "Управление производством",
  full: "Manufacturing Execution System",  // расшифровка
  aka: ["СОУП", "MOM", ...],      // синонимы / близкие названия
  what: "Мост между планом из ERP и реальным цехом...",  // простыми словами
  pain: "План «спускают» в цех на бумаге...",            // какую боль решает
  metrics: [                      // ровно 3 метрики
    { v: "+15%", l: "загрузка оборудования (OEE)" },
    { v: "−30%", l: "простои без причин" },
    { v: "партия", l: "полная прослеживаемость" }
  ],
  vendors: ["GT STOCK WMS (GTLogistics)", ...],  // [] если нет — покажется заглушка
  related: ["ERP", "ASUTP", "EAM", "WMS"],       // коды смежных классов
  client: "Дискретное и непрерывное производство..."
}
```

### Производные индексы
- `window.CLASS_BY_CODE` — быстрый доступ к классу по коду.
- `window.classLabel(c)` — метка класса (принимает код или объект).

## Как редактировать контент

Контент правится **через админку** (`/admin.html`, вход по паролю администратора) — изменения сразу сохраняются в хранилище и видны всем. Сид-данные в `lib/seed.js` используются только при первом запуске (пустое хранилище) и как образец структуры.

| Задача | Где в админке |
|--------|---------------|
| Тексты карточки (название, расшифровка, «что это», «боль», клиент, метрики, синонимы, вендоры) | вкладка **Классы** → выбрать класс |
| Добавить / удалить класс | вкладка **Классы** → «+ Добавить класс» / «Удалить класс» |
| Переместить метку на диораме | на карте: **✎ Метки** → перетащить → **Сохранить** (или поля «Позиция X/Y» в админке) |
| Названия и цвета зон, координаты | вкладка **Зоны** |
| Тексты шапки и подсказок | вкладка **Шапка** |
| Сменить пароли (сайт / админ) | вкладка **Доступ** |
| Сменить логотип / картинки этажей | заменить файлы в `assets/` (`floor1.png` / `floor2.png` / `globus-logo.svg`) через git |

> **Важно:** «Что стоит рядом» — это коды (`code`) других классов через запятую; ссылайтесь только на существующие коды, иначе чип не отрисуется. «Свой» продукт (Globus) подсвечивается автоматически, если в строке вендора есть `globus / compo / 1с глобус / g-hunt`.

## Архитектура и поток состояния

```
App (состояние: selected, glossaryOpen, tweaks)
├── header.topbar            переключатель режима, словарь, тема
└── stage-wrap
    ├── Sidebar              карточка выбранного класса (selected)
    ├── main.stage
    │   ├── DioramaMap  ──┐  один из двух в зависимости от t.mode
    │   └── BuildingMap ──┘
    └── Glossary            словарь (glossaryOpen)
```

- Единственный источник правды о выбранном классе — `selected` (код) в `App`.
- Выбор класса (из диорамы, схемы, словаря или чипа «что стоит рядом») идёт через колбэк `onSelect(code)`.
- `focusedZone` вычисляется из выбранного класса при включённом автозуме и передаётся в карту для зумирования.
- Настройки (`t`) хранятся в `useTweaks` и применяются как CSS-классы на корневом `.app`.

## Известные ограничения

- **Нужен интернет** для React, Babel и шрифтов (CDN). Полностью офлайн работать не будет без локализации этих ресурсов.
- **In-browser Babel** медленнее предсобранного кода — для продакшена JSX стоит прекомпилировать.
- **Размер картинок этажей** (~4,5 МБ PNG каждая) — основной вес страницы; при необходимости оптимизировать (WebP/сжатие).
- **Авто-миграция контента:** `store.js` сравнивает формат данных в KV и, если он старый (у зон нет поля `building`), перезаписывает его сидом `seed.js`. Это разовый предохранитель миграции на двухэтажную версию.
- Это **прототип/handoff-дизайн**, а не продакшен-сборка. Для встраивания в реальный сайт рекомендуется перенести на нормальный bundler (Vite/Next) и вынести данные в отдельный модуль/CMS.

## Деплой

Хостинг — **Vercel**. Фронтенд отдаётся статикой, `/api/*` исполняется как serverless-функции, контент и пароли лежат в Vercel KV.

**Автодеплой по `git push`:** репозиторий подключён к проекту Vercel (Settings → Git). Каждый пуш в ветку `main` автоматически публикует новую версию в продакшен; пуши в другие ветки/PR дают preview-деплои.

**Первичная настройка (однократно):**
1. В Vercel → проект → **Storage** → создать **KV (Upstash Redis)** и привязать к проекту (переменные `KV_REST_API_URL/TOKEN` добавятся сами).
2. Задать `AUTH_SECRET` (длинная случайная строка) в **Settings → Environment Variables**.
3. (Опционально) `DEFAULT_VIEWER_PASSWORD` / `DEFAULT_ADMIN_PASSWORD` — иначе пароли по умолчанию `globus` / `globus-admin`.
4. Подключить Git-репозиторий (Settings → Git) для автодеплоя.

**Ручной деплой через CLI:** из корня проекта `npx vercel --prod`.

> После первого деплоя зайдите в `/admin.html` и **смените оба пароля** во вкладке «Доступ».
