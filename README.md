# Карта ИТ-предприятия · Globus IT

Интерактивная одностраничная карта классов корпоративных ИТ-решений. Пользователь рассматривает «разрез» условного предприятия (цех, склад, дата-центр, офисы) и кликает на любую систему, чтобы открыть карточку класса решений: что это, какую боль решает, эффект в цифрах, вендоры Globus и смежные классы.

Проект — самодостаточный HTML-файл: открывается двойным кликом в браузере, без сборки и сервера (нужен только доступ в интернет для CDN React и шрифтов).

---

## Быстрый старт

1. Откройте `index.html` в современном браузере (Chrome, Safari, Firefox, Edge).
2. Рядом с HTML должна лежать папка `assets/` с файлами `diorama.png` и `globus-logo.svg`.

> **Если карточки не открываются при открытии через `file://`** — некоторые браузеры ограничивают локальные скрипты. Запустите простой локальный сервер из папки проекта:
> ```bash
> python3 -m http.server 8000
> # затем откройте http://localhost:8000/Карта%20ИТ-предприятия.html
> ```

## Структура файлов

```
IT CLASSES WEB SITE/
├── index.html                  # всё приложение в одном файле
└── assets/
    ├── diorama.png             # растровая иллюстрация-диорама предприятия (~7,5 МБ)
    └── globus-logo.svg         # логотип Globus в шапке
```

Внутри HTML-файла код разбит на отдельные `<script>`-блоки (по смыслу — модули):

| Блок | Назначение |
|------|-----------|
| `<style>` в `<head>` | все стили (CSS-переменные, темы, компоненты, 3 стиля схемы) |
| Data layer | `window.ZONES`, `window.FLOOR_ORDER`, `window.CLASSES` — весь контент |
| Tweaks panel | плавающая панель настроек (режим, тема, поведение) |
| BuildingMap | SVG-разрез здания (режим «Схема») |
| DioramaMap | растровая диорама с хотспотами, zoom/pan (режим «Диорама») |
| Sidebar | левая выдвижная карточка класса |
| Glossary | правый выдвижной словарь аббревиатур с поиском |
| App | оболочка: шапка, состояние, переключение режимов |

## Технологический стек

- **React 18** + **ReactDOM** — через CDN (`unpkg.com`), development-сборки.
- **Babel Standalone** — JSX компилируется прямо в браузере (`<script type="text/babel">`).
- **Чистый CSS** — без препроцессоров; темизация через CSS-переменные и `color-mix()`.
- **SVG** — режим «Схема» рисуется как векторный разрез здания.
- **Шрифты Google Fonts**: Onest (заголовки), Golos Text (текст), JetBrains Mono (коды/моноширинный).

Сборка не требуется. Цена за это — Babel транспилирует JSX при каждой загрузке (в консоли будет предупреждение «You are using the in-browser Babel transformer» — это нормально для прототипа).

## Возможности

### Два режима карты
- **Диорама** — реалистичная изометрическая иллюстрация (`diorama.png`) с кликабельными хотспотами поверх. Поддерживает:
  - зум колесом мыши (к курсору), кнопками `＋ / －`, сброс кнопкой `⤢`;
  - перемещение (pan) правой или средней кнопкой мыши;
  - автозум к зоне при выборе класса (отключается в настройках).
- **Схема** — SVG-разрез здания: 5 этажей-зон, в каждой «комнате» — класс решений. Подсветка и hover-эффекты.

### Карточка класса (Sidebar)
При клике на систему слева выезжает панель:
- аббревиатура и полная расшифровка;
- синонимы и близкие названия («Также называют»);
- «Что это простыми словами»;
- «Какую боль решает»;
- «Эффект в цифрах» — 3 метрики;
- «Наши вендоры и продукты» (продукты Globus выделены цветом);
- «Типовой клиент и отрасль»;
- «Что стоит рядом» — переходы к смежным классам.

### Словарь (Glossary)
Правая панель с поиском по всем аббревиатурам, расшифровкам, названиям и синонимам. Клик по элементу открывает соответствующую карточку.

### Темизация и настройки
- Светлая / тёмная тема (кнопка в шапке).
- Плавающая панель настроек (Tweaks): режим карты, тёмный фон, автозум к зоне, пульсация маркеров.

### Управление с клавиатуры
- `Esc` — закрыть карточку и словарь.

## Модель данных

Весь контент описан в блоке Data layer. Менять тексты и наполнение можно прямо там — перезагрузка страницы подхватит изменения.

### Зоны — `window.ZONES`
5 функциональных зон предприятия. Каждая зона:

```js
production: {
  id: "production",
  title: "Производство и цех",   // полное название (заголовок в карточке)
  short: "Производство",          // короткая метка (ключ зон, ярлыки)
  accent: "#C8743A",              // акцентный цвет зоны
  tint: "#F8EDE2",                // светлый фон-подложка
  cx: 25, cy: 34,                 // центр зоны на диораме, в % (для автозума)
  floor: 2                        // порядковый номер этажа
}
```

Зоны: `production` (Производство), `logistics` (Склад и логистика), `data` (Дата-центр и кибербез), `sales` (Офис продаж и маркетинг), `back` (Бэк-офис).

### Порядок этажей — `window.FLOOR_ORDER`
Массив id зон сверху вниз для режима «Схема»:
```js
["sales", "back", "production", "logistics", "data"]
```

### Классы решений — `window.CLASSES`
Массив из 32 классов. Каждый класс:

```js
{
  code: "MES",                    // уникальный код (ключ)
  label: "MES",                   // отображаемая метка
  zone: "production",             // id зоны (связь с ZONES)
  pos: { x: 24, y: 36 },          // позиция хотспота на диораме, в %
  name: "Управление производством",
  full: "Manufacturing Execution System",  // расшифровка
  aka: ["СОУП", "MOM", ...],      // синонимы / близкие названия
  what: "Мост между планом из ERP и реальным цехом...",  // простыми словами
  pain: "План «спускают» в цех на бумаге...",            // какую боль решает
  metrics: [                      // ровно 3 метрики
    { v: "+15%", l: "загрузка оборудования (OEE)" },
    { v: "−30%", l: "простои без причин" },
    { v: "партия", l: "полная прослеживаемость" }
  ],
  vendors: ["GT STOCK WMS (GTLogistics)", ...],  // [] если нет — покажется заглушка
  related: ["ERP", "ASUTP", "EAM", "WMS"],       // коды смежных классов
  client: "Дискретное и непрерывное производство..."
}
```

### Производные индексы
- `window.CLASS_BY_CODE` — быстрый доступ к классу по коду.
- `window.classLabel(c)` — метка класса (принимает код или объект).

## Как редактировать контент

| Задача | Где менять |
|--------|-----------|
| Изменить текст карточки | объект класса в `window.CLASSES` |
| Добавить класс | новый объект в `window.CLASSES` + хотспот появится автоматически по `pos` |
| Переместить хотспот на диораме | поле `pos: { x, y }` (проценты от размера изображения) |
| Изменить цвет зоны | `accent` / `tint` в `window.ZONES` |
| Выделить продукт как «свой» (Globus) | в `vendors` строка должна содержать `globus / compo / 1с глобус / g-hunt` — регулярка в Sidebar подсветит её |
| Сменить логотип / диораму | заменить файлы в `assets/` |

> **Важно:** при добавлении класса убедитесь, что `zone` ссылается на существующую зону, а коды в `related` соответствуют реальным `code` других классов — иначе чип просто не отрисуется.

## Архитектура и поток состояния

```
App (состояние: selected, glossaryOpen, tweaks)
├── header.topbar            переключатель режима, словарь, тема
└── stage-wrap
    ├── Sidebar              карточка выбранного класса (selected)
    ├── main.stage
    │   ├── DioramaMap  ──┐  один из двух в зависимости от t.mode
    │   └── BuildingMap ──┘
    └── Glossary            словарь (glossaryOpen)
```

- Единственный источник правды о выбранном классе — `selected` (код) в `App`.
- Выбор класса (из диорамы, схемы, словаря или чипа «что стоит рядом») идёт через колбэк `onSelect(code)`.
- `focusedZone` вычисляется из выбранного класса при включённом автозуме и передаётся в карту для зумирования.
- Настройки (`t`) хранятся в `useTweaks` и применяются как CSS-классы на корневом `.app`.

## Известные ограничения

- **Нужен интернет** для React, Babel и шрифтов (CDN). Полностью офлайн работать не будет без локализации этих ресурсов.
- **In-browser Babel** медленнее предсобранного кода — для продакшена JSX стоит прекомпилировать.
- **Размер диорамы** (~7,5 МБ PNG) — основной вес страницы; при необходимости оптимизировать (WebP/сжатие).
- Это **прототип/handoff-дизайн**, а не продакшен-сборка. Для встраивания в реальный сайт рекомендуется перенести на нормальный bundler (Vite/Next) и вынести данные в отдельный модуль/CMS.

## Деплой

Сайт статический — никакой сборки не требуется. Хостится на **Vercel** как обычный набор файлов: `index.html` отдаётся из корня, рядом лежит `assets/`.

- **Через Git:** запушьте репозиторий на GitHub и импортируйте его в Vercel (Framework Preset: *Other*, build-команда не нужна). Каждый `git push` в основную ветку публикует новую версию.
- **Через CLI:** из корня проекта `npx vercel` (preview) или `npx vercel --prod` (продакшен).
